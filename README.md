# News Bot

Telegram-бот, который присылает новые посты из выбранных каналов **сразу после
публикации**. Расписания и дайджестов нет: как только сборщик увидел новый пост,
он уходит всем подписчикам этого канала.

- **Бот и команды** — [aiogram 3](https://docs.aiogram.dev/): приём апдейтов,
  управление подписками, отправка постов.
- **Сбор** — отдельный Telegram-аккаунт (Telethon/userbot). Он читает публичные каналы
  по `@username` и закрытые — если состоит в них. Bot API не умеет читать историю
  каналов, поэтому для этой части нужен userbot.
- **Хранилище** — SQLite: пользователи, каналы, подписки, посты.
- **Доставка** — после каждого канала сборщик рассылает новые посты его подписчикам,
  не дожидаясь конца прохода.

## Быстрый старт

### 1. Зависимости

Нужен Python 3.11+ (проект проверен на 3.14).

```bash
cd "News bot"
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Токен бота

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Скопируйте токен вида `123456789:AA...` в `BOT_TOKEN`.

### 3. Доступ к чтению каналов

1. Зайдите на <https://my.telegram.org/apps> под аккаунтом, который будет читать каналы.
   Лучше использовать **отдельный аккаунт**, а не основной.
2. Создайте приложение и возьмите `api_id` и `api_hash`.
3. Заполните их в `.env` и выполните:

```bash
python login.py
```

Скрипт попросит номер телефона, код из Telegram и пароль 2FA (если включён).
В конце он напечатает строку:

```
TELEGRAM_SESSION=1BVtsOK...
```

Вставьте её в `.env`. Строка даёт полный доступ к аккаунту — не публикуйте её и не
коммитьте `.env` в git (он уже в `.gitignore`).

Альтернатива — файловая сессия:

```bash
python login.py --file
```

Тогда в `.env` укажите `TELEGRAM_SESSION_PATH=data/newsbot.session` и оставьте
`TELEGRAM_SESSION` пустым.

### 4. Конфигурация

```bash
cp .env.example .env
```

Минимум, что нужно заполнить: `BOT_TOKEN`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`,
`TELEGRAM_SESSION`. Остальное можно оставить по умолчанию.

### 5. Запуск

```bash
source .venv/bin/activate
python main.py
```

В логе появится `Бот запущен: @your_bot`. Откройте бота в Telegram и отправьте `/start`.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Регистрация, подписка на каналы из `.env` при `AUTO_SUBSCRIBE_ENV_CHANNELS=true` |
| `/addchannel @name` | Проверить канал через Telegram и добавить в источники |
| `/delchannel @name` или `/delchannel 2` | Убрать канал (по ссылке или номеру из `/channels`) |
| `/channels` | Список каналов, последний пост, ошибки доступа |
| `/settings` | Статус уведомлений, число каналов, интервал проверки |
| `/pause`, `/resume` | Выключить/включить уведомления |
| `/help` | Подсказка |

Пример:

```
/addchannel @rian_ru
/channels
```

## Каналы: `.env` или база

Оба варианта поддерживаются.

- **`.env`** — `SOURCE_CHANNELS=@rian_ru,@telegram`. При старте они добавляются в таблицу
  `channels` с пометкой `source='env'`. При `AUTO_SUBSCRIBE_ENV_CHANNELS=true` каждый
  новый пользователь автоматически подписывается на них.
- **База** — всё, что добавлено через `/addchannel`, лежит в `channels` и
  `user_channels`. Это основной способ: каналы у разных пользователей могут быть разными.

Закрытые каналы: аккаунт-сборщик должен быть их участником. Приватные инвайт-ссылки
(`t.me/+...`) не поддерживаются — добавьте канал по `@username`, числовому ID
(`-100...`) или ссылке `t.me/c/...`, но только если аккаунт уже в канале.

## Как работает рассылка

- Каждые `COLLECT_INTERVAL_SECONDS` (по умолчанию 60 с) сборщик проверяет каналы,
  у которых есть хотя бы один подписчик.
- Новый пост сохраняется в `posts` и **сразу** отправляется всем активным подписчикам
  этого канала. Отдельного планировщика и «времени рассылки» нет.
- **Первый проход** по каналу забирает до `INITIAL_FETCH_LIMIT` последних постов, но
  подписчикам уходит только последний. Остальные остаются в истории и повторно не
  отправляются — чтобы после `/addchannel` не прилетал залп старых новостей.
- `/pause` выключает только доставку: сбор продолжается, курсор канала двигается
  вперёд. Пропущенные на паузе посты **не** досылаются — после `/resume` приходят
  только новые.
- Если бот упал между сохранением поста и отправкой, очередь (`posts.notified_at IS NULL`)
  доставляется при следующем запуске.
- Если пользователь заблокировал бота, его уведомления выключаются автоматически.
- `FloodWait` от Telegram: бот ждёт и повторяет операцию; при отправке — одна повторная
  попытка.
- Медиа не пересылается: в сообщении текст, отметка о медиа и ссылка на оригинал.

## Обновление со старой версии

База прежних версий мигрирует автоматически при старте:

- из `users` удаляются `timezone`, `digest_time`, `last_digest_at`, `last_digest_date`;
- в `posts` добавляется `notified_at`, а старые посты помечаются как уже разосланные —
  повторной рассылки истории не будет;
- таблица `users` пересобирается с сохранением id, поэтому подписки не теряются.

Переменные `DEFAULT_DIGEST_TIME`, `DIGEST_MAX_POSTS`, `SEND_EMPTY_DIGEST` больше не
используются и игнорируются. `DEFAULT_TIMEZONE` читается как устаревшее имя
`DISPLAY_TIMEZONE`.

## Настройки `.env`

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | Токен от @BotFather, обязателен |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | — | Данные приложения my.telegram.org |
| `TELEGRAM_SESSION` | — | Строка сессии из `login.py` |
| `TELEGRAM_SESSION_PATH` | `data/newsbot.session` | Файл сессии, если строка не задана |
| `DATABASE_PATH` | `data/newsbot.sqlite3` | Путь к SQLite |
| `DISPLAY_TIMEZONE` | `Europe/Moscow` | Часовой пояс для времени в сообщениях |
| `SOURCE_CHANNELS` | пусто | Каналы через запятую/пробел |
| `AUTO_SUBSCRIBE_ENV_CHANNELS` | `true` | Подписывать новых пользователей на `SOURCE_CHANNELS` |
| `COLLECT_INTERVAL_SECONDS` | `60` | Период опроса каналов, минимум 30 |
| `INITIAL_FETCH_LIMIT` | `20` | Глубина первого чтения канала |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING` |

Если `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` не заданы, бот запускается в урезанном режиме:
команды работают, сбор — нет. Для полноценной работы нужны все три параметра и
авторизованная сессия.

## Данные и логи

- `data/newsbot.sqlite3` — база (WAL-режим).
- `data/newsbot.log` — лог с ротацией (5 МБ × 3).
- `data/newsbot.session` — файловая сессия, если используется.

Удаление `data/` сбрасывает всё. Перед этим остановите бота.

## Docker

```bash
cp .env.example .env
# заполните .env, TELEGRAM_SESSION рекомендуется получить на хосте
mkdir -p data
docker compose up -d --build
docker compose logs -f
```

`docker-compose.yml` монтирует `./data` в контейнер, поэтому база и логи сохраняются.

## Частые проблемы

**`Канал не найден или аккаунт не состоит в нём`**
Проверьте, что сессия из `TELEGRAM_SESSION` принадлежит аккаунту, который видит канал.
Для закрытого канала вступите в него под этим аккаунтом. Для публичного достаточно
`@username`.

**`Аккаунт-сборщик не состоит в этом канале`**
То же: добавьте аккаунт в канал. Боты-админы тут не помогут — читает userbot.

**После `/addchannel` пришёл только один пост**
Так и задумано: история не рассылается, последний пост приходит как точка входа.

**Новые посты приходят с задержкой**
Задержка — до одного интервала `COLLECT_INTERVAL_SECONDS` (по умолчанию 60 с). Если в
`.env` осталось старое значение `300`, посты будут приходить до 5 минут. Проверьте
`/settings`: там виден интервал и время последней проверки.

**После `/resume` пропущенные посты не пришли**
Так и задумано: пауза отключает уведомления, а не откладывает их. Придут только новые.

**`FloodWaitError`**
Telegram ограничил частоту запросов. Бот подождёт и продолжит; увеличьте
`COLLECT_INTERVAL_SECONDS`, если каналов много.

**`Telegram-аккаунт для сбора новостей не авторизован`**
Выполните `python login.py` и обновите `TELEGRAM_SESSION`. Если сессия отозвана,
повторите вход.

**Ошибка `database is locked`**
Не запускайте два процесса бота на одной базе. SQLite в WAL рассчитан на один писатель.

## Ограничения и безопасность

- Userbot — автоматизация обычного аккаунта. Telegram может ограничить аккаунт за
  агрессивное поведение; используйте отдельный аккаунт, умеренный интервал и не
  добавляйте десятки каналов без необходимости.
- Бот не пересылает медиа: в сообщении текст, отметка о медиа и ссылка на пост.
- Приватные инвайт-ссылки не поддерживаются.
- `.env`, строку сессии и `data/` нельзя публиковать: это доступ к боту и аккаунту.
- Бот не является архиватором: храните резервные копии `data/newsbot.sqlite3`, если
  история постов важна.
